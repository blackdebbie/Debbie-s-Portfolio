01 Introduction

Healthcare systems today are not lacking technology.

They are failing because:

  • systems are disconnected
  • workflows are not respected
  • tools are not built around real users

Doctors, nurses, and patients use different systems that do not communicate, leading to delays, confusion, and errors.

Research shows that healthcare UX must be based on real workflows, not assumptions, using interviews, workflow analysis, and persona mapping to understand users properly (Neuron)

02 Problem Definition

From initial research, the problems were grouped into system-level issues:

Administrative Overload

Doctors and nurses spend more time:

  • documenting
  • switching systems
  • searching for patient data

This slows down care.

Fragmented Patient Records

Patient data is:

  • scattered
  • inconsistent
  • hard to access

Poor Communication

  • Nurses update → doctors are not clearly notified
  • Doctors decide → patients don’t get clear updates

Lack of Real-Time System

  • Updates are delayed
  • Information becomes outdated

Disconnected Systems

  • Patient apps
  • Staff dashboards
  • Admin tools

All operate separately.

03 Research Process

I did not start with UI.

I started by understanding how the system works in real life.

1. Product & System Understanding

First, I mapped how hospitals currently operate:

  • patient registration
  • nurse interaction
  • doctor decision
  • continuous care across shifts

This helped me understand where breakdown happens in the workflow

2. User Research (Interviews + Observation)

I focused on three main user groups:

  • Patients
  • Nurses
  • Doctors

Instead of asking what features they want, I focused on:

  • what they do daily
  • where they struggle
  • what slows them down

This approach is important because healthcare UX research focuses on real tasks and frustrations, not feature requests (UX Studio)

Key Findings from Research

Doctors

  • overwhelmed by too much data
  • need quick decisions, not exploration
  • frustrated by switching between systems

Nurses

  • work in repetitive tasks
  • need speed and clarity
  • struggle with documentation duplication

Patients

  • confused by medical information
  • want simple guidance
  • need reminders and updates
04 Persona Creation (Used for Decision-Making)

Instead of creating decorative personas, I created functional personas based on behavior.

01
The Decision-Maker (Doctor)
  • Works in high-pressure environments
  • Has limited time
Needs:
  • quick access to critical data
  • minimal clicks
  • clear actions
02
The Executor (Nurse)
  • Handles multiple patients
  • Performs repeated tasks
Needs:
  • structured workflow
  • fast input system
  • minimal errors
03
The Dependent User (Patient)
  • Not medically trained
  • Needs clarity
Needs:
  • simple explanations
  • reminders
  • easy navigation

Why Personas Were Important

They helped answer questions like:

  • Should patients see all data? → No (they need clarity, not overload)
  • Should nurses approve data? → No (accuracy requires doctor validation)
  • Should doctors navigate deeply? → No (they need fast decisions)
The system must match how each user thinks and works. Key Insight
  • • Doctor → problem → data → decision
  • • Nurse → task → update → complete
  • • Patient → understand → act
05 Design Strategy

1. Build a Central System (EHR)

Decision: Create one shared patient record.

Why: Without a single source of truth:

  • data becomes inconsistent
  • communication breaks
  • errors increase

2. Role-Based Design

Decision: Same data, different interfaces.

Why: Each user has different goals:

  • patients → clarity
  • nurses → execution
  • doctors → decision

3. Closed-Loop Workflow

Decision: Every action must return a result.

Flow: nurse updates → doctor reviews → patient sees outcome

Why: Prevents:

  • lost updates
  • confusion
  • incomplete care

4. Approval System (Critical Decision)

Decision: All updates must be approved by a doctor.

Why: From research:

  • nurses input data
  • doctors validate decisions

This ensures:

  • safety
  • accuracy
  • accountability

5. Context-Based Communication

Decision: No separate chat system.

Why: Research showed:

  • switching tools breaks workflow
  • messages lose context

Solution: Communication happens inside patient profile.

6. Real-Time System

Decision: All updates are instant.

Why: Healthcare decisions depend on:

  • current data
  • not delayed information
06 Solution

A connected system with 3 layers:

Access Layer

Patient Mobile App

Designed based on patient persona.

Features:

  • health summary
  • medication reminders
  • health tracking (8 weeks)
  • reports
  • notifications
  • payments
  • emergency call
  • health tips
Execution Layer

Nurse Dashboard

Designed based on nurse persona.

Features:

  • patient list
  • task system
  • add patient
  • update vitals
  • notes
Decision Layer

Doctor Dashboard

Designed based on doctor persona.

Features:

  • patient overview
  • pending approvals
  • alerts (critical only)
  • diagnosis and prescription
  • communication

08 Key Design Decisions (Backed by Research)

Simplicity over Features

Users prefer clarity over complexity in healthcare systems (Aufait UX)

Reduce Cognitive Load

Too much information slows decisions and increases risk (Aufait UX)

Task-Based Design

Healthcare users focus on completing tasks, not exploring systems

Real-Time Feedback

Immediate updates improve efficiency and care quality
